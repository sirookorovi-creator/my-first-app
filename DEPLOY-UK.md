# Запуск VOXBRIDGE на Cloudflare — простими кроками

Це **інструкція для власника**. Програму й перевірки коду вже підготовлено. Поки немає підключення до Cloudflare, справжній сайт не запущено. **Нічого не купуйте без перевірки тарифів.**

## Що вже зроблено без участі власника

- Робочий код Cloudflare Worker, сайт для смартфонів і SQL-схема.
- Автоматичні серверні тести через GitHub Actions.
- Обмеження кількості AI-запитів, щоб зменшити ризик неочікуваних витрат.
- Окремий **ручний** механізм публікації: `.github/workflows/deploy.yml`. Він не запускається від кожної зміни коду.

## Що потрібно один раз підключити власнику

### 1. Cloudflare

Відкрийте https://dash.cloudflare.com/ та увійдіть або створіть акаунт.

База даних **`voxbridge-db`** вже створена власником, а її **Database ID** уже внесено безпосередньо в `wrangler.jsonc`. Нічого повторно створювати чи копіювати не потрібно.

Знайдіть свій **Account ID** у Cloudflare Dashboard.

Створіть **API token** для деплою, обмежений цим акаунтом. Для першого створення Worker потрібні відповідні дозволи на **Workers Admin**; для застосування міграцій бази — доступ на редагування D1. Дозволів на інші акаунти не надавайте.

### 2. GitHub: додати лише налаштування, а не код

Репозиторій: https://github.com/sirookorovi-creator/my-first-app

У **Settings → Secrets and variables → Actions → Secrets** створіть дві **Repository secrets**:

- `CLOUDFLARE_ACCOUNT_ID` — Account ID із Cloudflare;
- `CLOUDFLARE_API_TOKEN` — створений Cloudflare API token.


**Не вставляйте жоден ключ у README, файли коду або чат.** Репозиторій наразі публічний.

### 3. Запустити автоматичне розгортання

Відкрийте репозиторій → **Actions** → **Deploy VOXBRIDGE (manual)** → **Run workflow**.

Автоматичний процес перевірить код, використає вже прописаний у `wrangler.jsonc` Database ID, застосує SQL-міграції й спробує розгорнути Worker та статичний сайт. У разі помилки дивіться журнал конкретного кроку.

Після успіху Wrangler покаже адресу на кшталт `https://voxbridge-mvp.<ваш-піддомен>.workers.dev`. Це приклад формату, **не поточна адреса запущеного сайту**.

### 4. Установити три серверні секрети Cloudflare

На сторінці створеного Worker, у налаштуваннях **Variables and Secrets**, додайте:

- `OPENAI_API_KEY` — окремий оплачуваний API-ключ OpenAI;
- `RATE_LIMIT_SALT` — новий випадковий рядок щонайменше з 20 символів;
- `LINK_SECRET` — *інший* випадковий рядок щонайменше з 24 символів.

На Mac два різні секрети можна згенерувати двома запусками `openssl rand -hex 32` у Terminal. Зберігайте їх у менеджері паролів. **Ніколи не змінюйте LINK_SECRET для чинної бази без плану міграції**: це зробить чинні запрошення недоступними для відновлення.

Підписка ChatGPT **не оплачує** використання OpenAI API. Спочатку встановіть у OpenAI жорсткий невеликий бюджет і перевірте поточні тарифи.

### 5. Перевірити запуск без вигаданих результатів

- Відкрийте `<ваша-адреса>/api/health`. Має повернути `{"ok":true,"aiConfigured":true}`; це лише технічна перевірка, не доказ якості перекладу.
- Відкрийте сайт на двох **реальних** телефонах (iPhone Safari й Android Chrome).
- Створіть одну розмову, запишіть коротке повідомлення, передайте запрошення, прослухайте переклад, дайте відповідь, перевірте видалення розмови.
- Перевірте витрати OpenAI після тесту.
- До публічного поширення додайте повноцінний антибот-захист, перегляньте політику приватності й підготуйте резервування даних за потреби.

## Статус та обмеження

**Станом на підготовку документа:** автоматичні серверні тести з підставними відповідями AI пройдено. Справжній Cloudflare deployment, дію реального OpenAI API і тест на фізичних телефонах **не підтверджено**. Мова інтерфейсу перемикається EN/UA, підтримуються 13 мов перекладу. Не стверджуйте, що продукт готовий до комерційного продажу.

Рекомендовано перевести GitHub-репозиторій з **Public** на **Private** перед роботою з комерційним кодом, а секрети зберігати лише в GitHub Secrets/Cloudflare.
